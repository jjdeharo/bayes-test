1. El problema: diagnosticar con pocas preguntas

Un test convencional hace las mismas preguntas a todos los alumnos y cuenta cuántas acierta. El resultado es un porcentaje. El problema es que muchas de esas preguntas son demasiado fáciles o demasiado difíciles para cada alumno concreto: aportan poca información útil y alargan el test innecesariamente.

Un test adaptativo elige cada pregunta en función de lo que ya sabe del alumno. Para ello necesita:

  1. Una representación del estado de conocimiento del alumno en cada momento.
  2. Un mecanismo para actualizar esa representación tras cada respuesta.
  3. Un criterio para elegir la pregunta que más información aportará.
  4. Un criterio para decidir cuándo ya sabe suficiente y puede parar.

Este sistema resuelve los cuatro puntos usando el teorema de Bayes para actualizar, la función logística IRT 3PL para calcular las verosimilitudes, y la entropía de Shannon para medir la incertidumbre y seleccionar preguntas.

2. El espacio de hipótesis y el prior inicial

El sistema no trabaja con una única estimación puntual del nivel del alumno, sino con una distribución de probabilidades sobre tres hipótesis:

HipótesisValor numérico \(\theta_i\)Significado
\(H_0\) — Básico\(\theta_0 = -1\)Conocimiento básico o escaso
\(H_1\) — Medio\(\theta_1 = 0\)Conocimiento medio o consolidado
\(H_2\) — Avanzado\(\theta_2 = +1\)Conocimiento avanzado o sólido

Los valores \(\theta_i\) están centrados en cero con separación unitaria. La misma escala se usa para la dificultad de las preguntas, lo que hace que la función logística produzca probabilidades coherentes entre niveles y dificultades.

Prior inicial: ignorancia total

Al comenzar el test, el sistema no sabe nada del alumno. Aplica el principio de indiferencia: si no hay razón para preferir una hipótesis sobre otra, se asignan probabilidades iguales.

\[ \pi^{(0)} = \bigl(P(H_0),\, P(H_1),\, P(H_2)\bigr) = \left(\tfrac{1}{3},\, \tfrac{1}{3},\, \tfrac{1}{3}\right) \approx (33{,}3\%,\; 33{,}3\%,\; 33{,}3\%) \]

Este vector \(\pi^{(0)}\) es el prior. Tras cada respuesta se convierte en el posterior, que pasa a ser el prior de la siguiente pregunta. Así, la estimación se refina de forma acumulativa.

Intuición La distribución no es una etiqueta sino un estado de conocimiento. Si \(P(H_1) = 0{,}70\), el sistema no afirma que el alumno es de nivel medio: afirma que, con los datos disponibles, el nivel medio es 3,5 veces más probable que cada uno de los otros dos.

3. El modelo IRT 3PL: cómo se calculan las verosimilitudes

Para actualizar con Bayes, el sistema necesita saber: «si el alumno fuera de nivel \(H_i\), ¿con qué probabilidad acertaría esta pregunta?» Esa probabilidad es la verosimilitud.

En lugar de fijar una tabla estática, el sistema calcula las verosimilitudes de forma dinámica para cada pregunta usando el modelo logístico IRT de tres parámetros (3PL):

\[ P(\text{acierto} \mid H_i,\, q) \;=\; c_q + (1 - c_q)\cdot\frac{1}{1 + e^{-a\,(\theta_i - b_q)}} \]

Los tres parámetros que dan nombre al modelo son:

  • \(b_q\) — dificultad de la pregunta: Fácil \(= -1\), Media \(= 0\), Difícil \(= +1\).
  • \(a = 1{,}5\) — discriminación: controla lo rápido que cambia la probabilidad alrededor de \(\theta = b_q\).
  • \(c_q = 1/m_q\) — acierto mínimo por azar: para 4 opciones, \(c_q = 0{,}25\).

La función logística y el parámetro de azar

La fracción \(\dfrac{1}{1+e^{-a(\theta_i-b_q)}}\) es la función logística estándar. Tiene forma de S:

  • Si \(\theta_i \gg b_q\) (alumno muy por encima de la dificultad): el exponente \(e^{-a(\theta_i-b_q)} \to 0\), la fracción tiende a 1.
  • Si \(\theta_i = b_q\) (alumno justo en la dificultad): la fracción vale exactamente \(0{,}5\).
  • Si \(\theta_i \ll b_q\) (alumno muy por debajo): la fracción tiende a 0.

El término \(c_q + (1-c_q)\cdot(\cdots)\) levanta el suelo de la curva hasta \(c_q\): ningún alumno puede tener una probabilidad de acierto menor que la de responder al azar. Cuando \(\theta_i = b_q\) exactamente, la probabilidad de acierto es:

\[ P(\text{acierto}) = c_q + (1-c_q)\cdot 0{,}5 = 0{,}25 + 0{,}75 \times 0{,}5 = 0{,}625 \]

Eso explica las entradas de la diagonal de la tabla siguiente (62,5 %).

Tabla completa de verosimilitudes de acierto (\(a = 1{,}5\), \(m_q = 4\), \(c_q = 0{,}25\))

Pregunta Básico \(\theta = -1\) Medio \(\theta = 0\) Avanzado \(\theta = +1\)
Fácil \(b=-1\) 62,5 % 86,3 % 96,4 %
Media \(b=0\) 38,7 % 62,5 % 86,3 %
Difícil \(b=1\) 28,6 % 38,7 % 62,5 %

Las celdas resaltadas son los puntos donde \(\theta_i = b_q\): siempre dan 62,5 %. La tabla muestra que la curva es simétrica respecto a esa diagonal.

Cálculo explícito: pregunta media, nivel medio

-- Parámetros: θ = 0 (Medio), b = 0 (Media), a = 1.5, c = 0.25 Exponente: −a·(θ − b) = −1.5·(0 − 0) = 0 Logística: 1 / (1 + e⁰) = 1 / (1 + 1) = 0.5 P(acierto): 0.25 + (1 − 0.25)·0.5 = 0.25 + 0.375 = 0.625 -- Pregunta media, nivel básico Exponente: −1.5·(−1 − 0) = +1.5 e^1.5 ≈ 4.4817 Logística: 1 / (1 + 4.4817) = 1 / 5.4817 ≈ 0.1824 P(acierto): 0.25 + 0.75·0.1824 = 0.25 + 0.1368 = 0.3868 ≈ 38.7 % -- Pregunta media, nivel avanzado Exponente: −1.5·(+1 − 0) = −1.5 e^−1.5 ≈ 0.2231 Logística: 1 / (1 + 0.2231) ≈ 0.8176 P(acierto): 0.25 + 0.75·0.8176 = 0.25 + 0.6132 = 0.8632 ≈ 86.3 %

Verosimilitud de fallo

Si el alumno falla, la verosimilitud es simplemente el complemento:

\[ P(\text{fallo} \mid H_i,\, q) = 1 - P(\text{acierto} \mid H_i,\, q) \]

Para una pregunta media, las verosimilitudes de fallo son:

NivelP(acierto)P(fallo)
Básico38,7 %61,3 %
Medio62,5 %37,5 %
Avanzado86,3 %13,7 %
Asimetría diagnóstica Un fallo en una pregunta media es muy informativo: un alumno básico la falla con 61,3 % de probabilidad, un avanzado solo con 13,7 %. La ratio es 4,5:1. En cambio, un acierto en esa misma pregunta es menos conclusivo: podría deberse a suerte (el alumno básico la acierta con 38,7 %). Los fallos son más diagnósticos que los aciertos en preguntas de opción múltiple porque el suelo de azar crea una asimetría.

4. La actualización bayesiana paso a paso

El teorema de Bayes toma el prior actual \(\pi^{(n)}\), la verosimilitud de la respuesta observada, y produce un nuevo posterior \(\pi^{(n+1)}\):

\[ \pi^{(n+1)}_i = P(H_i \mid R) = \frac{P(R \mid H_i)\cdot \pi^{(n)}_i}{\displaystyle\sum_j P(R \mid H_j)\cdot \pi^{(n)}_j} \]

El denominador es simplemente la suma de todos los numeradores: garantiza que el posterior sume 1 (normalización).

Ejemplo: primera pregunta, pregunta media, respuesta incorrecta

1
Prior inicial: \(\pi = (1/3,\; 1/3,\; 1/3)\). El alumno falla una pregunta media (\(b_q = 0\), \(m_q = 4\)).
2
Verosimilitudes de fallo (complementos de la tabla anterior): \[P(\text{fallo} \mid H_0) = 0{,}613 \qquad P(\text{fallo} \mid H_1) = 0{,}375 \qquad P(\text{fallo} \mid H_2) = 0{,}137\]
3
Productos verosimilitud × prior (numeradores sin normalizar): \[\text{Básico: } 0{,}613 \times \tfrac{1}{3} = 0{,}2043 \qquad \text{Medio: } 0{,}375 \times \tfrac{1}{3} = 0{,}1250 \qquad \text{Avanzado: } 0{,}137 \times \tfrac{1}{3} = 0{,}0457\]
4
Denominador (normalización): \(\; 0{,}2043 + 0{,}1250 + 0{,}0457 = 0{,}3750\)
5
Posterior: \[P(H_0 \mid \text{fallo}) = \frac{0{,}2043}{0{,}3750} \approx \mathbf{54{,}5\%} \qquad P(H_1 \mid \text{fallo}) = \frac{0{,}1250}{0{,}3750} \approx \mathbf{33{,}3\%} \qquad P(H_2 \mid \text{fallo}) = \frac{0{,}0457}{0{,}3750} \approx \mathbf{12{,}2\%}\]
Resultado Con una sola respuesta, el sistema pasa de una distribución completamente plana (33 %, 33 %, 33 %) a otra con una hipótesis claramente dominante (54,5 %, 33,3 %, 12,2 %). El nivel Básico es ahora 4,5 veces más probable que el Avanzado.

Este posterior \(\pi^{(1)} = (0{,}545,\; 0{,}333,\; 0{,}122)\) pasa a ser el prior de la siguiente pregunta. El proceso se repite tras cada respuesta, acumulando evidencia.

¿Por qué no se usa la fórmula de Bayes original con denominador explícito?

La fórmula clásica \(P(H\mid E) = P(E\mid H)\,P(H)/P(E)\) requiere calcular \(P(E)\) como la probabilidad total de la evidencia. Con múltiples hipótesis, esa cantidad es exactamente la suma del denominador, es decir:

\[ P(E) = \sum_j P(E \mid H_j)\,P(H_j) \]

El denominador de normalización es \(P(E)\). Calcularlo explícitamente como suma es equivalente y más directo cuando se trabaja con vectores.

5. La entropía de Shannon como termómetro de incertidumbre

Después de cada actualización, el sistema necesita saber cuánta incertidumbre queda. Para eso usa la entropía de Shannon:

\[ H(\pi) = -\sum_{i} \pi_i \log_2 \pi_i \qquad \text{(con la convención } 0\cdot\log_2 0 = 0\text{)} \]

La entropía se mide en bits (al usar logaritmo en base 2). Tiene propiedades clave:

  • Máxima cuando todas las hipótesis son equiprobables: no se sabe nada.
  • Cero cuando una hipótesis tiene probabilidad 1: certeza absoluta.
  • Estrictamente decreciente con la concentración de la distribución.

Valores concretos del sistema

DistribuciónEntropíaInterpretación
\((1/3,\; 1/3,\; 1/3)\)\(\log_2 3 \approx 1{,}585\) bitsIgnorancia total (prior inicial)
\((0{,}545,\; 0{,}333,\; 0{,}122)\)\(\approx 1{,}375\) bitsTras un fallo en pregunta media
\((0{,}80,\; 0{,}10,\; 0{,}10)\)\(\approx 0{,}922\) bitsUmbral de parada \(H_\text{stop}\)
\((1{,}0,\; 0{,}0,\; 0{,}0)\)\(0\) bitsCerteza absoluta (imposible en la práctica)

Cálculo de la entropía tras el primer fallo

-- Prior tras fallo en media: π = (0.545, 0.333, 0.122) Básico: 0.545 × log₂(0.545) = 0.545 × (−0.875) = −0.477 Medio: 0.333 × log₂(0.333) = 0.333 × (−1.585) = −0.528 Avanzado: 0.122 × log₂(0.122) = 0.122 × (−3.036) = −0.370 H(π) = −(−0.477 − 0.528 − 0.370) = 1.375 bits -- Reducción respecto al prior inicial: ΔH = 1.585 − 1.375 = 0.210 bits reducidos (13 % del recorrido total)
Intuición de la fórmula Cada término \(-p_i \log_2 p_i\) mide la «sorpresa» esperada si la hipótesis \(i\) fuera cierta. Si \(p_i = 1\), no hay sorpresa (\(-1\cdot 0 = 0\)). Si \(p_i = 0{,}5\), la sorpresa es 1 bit (como una moneda). La entropía total es la media ponderada de las sorpresas de todas las hipótesis.

6. Selección de la siguiente pregunta: ganancia esperada de información

El sistema no elige preguntas al azar ni simplemente sube la dificultad tras un acierto. Simula el futuro: para cada pregunta disponible, calcula cuánta incertidumbre esperaría reducir antes de mostrarla.

La ganancia esperada de información (también llamada información mutua) de la pregunta \(q\) respecto al prior actual \(\pi\) es:

\[ IG(q) = H(\pi) - \Bigl[P(A)\cdot H(\pi_A) + P(F)\cdot H(\pi_F)\Bigr] \]

Donde:

  • \(P(A) = \sum_i \pi_i \cdot P(\text{acierto}\mid H_i,q)\) es la probabilidad marginal de que el alumno acierte (ley de la probabilidad total).
  • \(P(F) = 1 - P(A)\).
  • \(\pi_A\) es el posterior simulado si el alumno aciertara (aún no ha respondido).
  • \(\pi_F\) es el posterior simulado si el alumno fallara.

Cálculo completo con el prior uniforme

Comparamos las tres categorías de preguntas partiendo de \(\pi^{(0)} = (1/3, 1/3, 1/3)\).

Pregunta fácil (\(b = -1\))

-- Verosimilitudes de acierto: (0.625, 0.863, 0.964) P(A) = (0.625 + 0.863 + 0.964) / 3 = 2.452 / 3 = 0.817 P(F) = 1 − 0.817 = 0.183 -- Posterior si acierta: π_A = (0.625/2.452, 0.863/2.452, 0.964/2.452) = (0.255, 0.352, 0.393) H(π_A) = 1.563 bits -- Posterior si falla: raw_F = (1/3·0.375, 1/3·0.137, 1/3·0.036) = (0.125, 0.046, 0.012) π_F = (0.125/0.183, 0.046/0.183, 0.012/0.183) = (0.683, 0.251, 0.066) H(π_F) = 1.131 bits IG(fácil) = 1.585 − [0.817·1.563 + 0.183·1.131] = 1.585 − [1.277 + 0.207] = 0.101 bits

Pregunta media (\(b = 0\))

-- Verosimilitudes de acierto: (0.387, 0.625, 0.863) P(A) = (0.387 + 0.625 + 0.863) / 3 = 1.875 / 3 = 0.625 P(F) = 0.375 -- Posterior si acierta: π_A = (0.387/1.875, 0.625/1.875, 0.863/1.875) = (0.206, 0.333, 0.460) H(π_A) = 1.513 bits -- Posterior si falla (ya calculado en §4): π_F = (0.545, 0.333, 0.122) H(π_F) = 1.375 bits IG(media) = 1.585 − [0.625·1.513 + 0.375·1.375] = 1.585 − [0.946 + 0.516] = 0.123 bits

Pregunta difícil (\(b = +1\))

-- Verosimilitudes de acierto: (0.286, 0.387, 0.625) P(A) = (0.286 + 0.387 + 0.625) / 3 = 1.298 / 3 = 0.433 P(F) = 0.567 -- Posterior si acierta: π_A = (0.286/1.298, 0.387/1.298, 0.625/1.298) = (0.220, 0.298, 0.482) H(π_A) = 1.509 bits -- Posterior si falla: raw_F = (1/3·0.714, 1/3·0.613, 1/3·0.375) = (0.238, 0.204, 0.125) π_F = (0.420, 0.360, 0.220) H(π_F) = 1.537 bits IG(difícil) = 1.585 − [0.433·1.509 + 0.567·1.537] = 1.585 − [0.653 + 0.871] = 0.061 bits

¿Por qué gana la pregunta media con prior uniforme? Con \(P(A) = 0{,}625\) y \(P(F) = 0{,}375\), una pregunta media produce un reparto casi óptimo de probabilidad entre acierto y fallo, con buenos ratios de verosimilitud entre niveles. La pregunta fácil tiene \(P(A) = 0{,}817\): casi siempre se acierta, y un acierto en una pregunta fácil apenas mueve la distribución. La difícil tiene \(P(A) = 0{,}433\): genera posteriors más concentrados pero con menor ganancia neta porque los valores de verosimilitud están más aplastados por el suelo de azar.

A medida que el prior cambia, también cambia qué pregunta es más informativa. Si tras varios fallos el sistema estima que el alumno es básico con alta probabilidad, una pregunta fácil puede ser más útil para distinguir entre «básico» y «muy básico». El cálculo de IG se repite en cada turno con el prior actualizado.

7. Criterio de parada dual

El test no termina después de un número fijo de preguntas. Se detiene cuando se cumplen simultáneamente dos condiciones (tras un mínimo de 6 preguntas):

\[ \text{(1)}\;\; H(\pi) < H_\text{stop} \qquad\text{y}\qquad \text{(2)}\;\; \max_i \pi_i \geq 0{,}80 \]

¿Por qué dos criterios?

\(H_\text{stop}\) se calcula asumiendo que la probabilidad residual \((1-p_\min)\) se reparte uniformemente entre las otras hipótesis. Eso es una aproximación. Con tres hipótesis, la distribución \((0{,}80,\; 0{,}10,\; 0{,}10)\) tiene la misma hipótesis máxima que \((0{,}80,\; 0{,}19,\; 0{,}01)\), pero entropías distintas:

H(0.80, 0.10, 0.10) = 0.922 bits ← umbral H_stop H(0.80, 0.19, 0.01) ≈ 0.834 bits ← diferente entropía, misma hipótesis máxima

Por eso se comprueba también la condición \(\max_i \pi_i \geq 0{,}80\): garantiza que la hipótesis más probable realmente supera el umbral de confianza, independientemente de cómo se distribuya el resto.

Derivación de \(H_\text{stop}\)

El umbral se define como la entropía de la distribución límite: la menos concentrada que aún cumple \(\max_i \pi_i = p_\min = 0{,}80\). Bajo el supuesto de reparto uniforme del resto:

\[ H_\text{stop} = -p_\min \log_2 p_\min - (1-p_\min)\log_2\!\left(\frac{1-p_\min}{n-1}\right) \]

Para \(n = 3\) hipótesis y \(p_\min = 0{,}80\):

p_min = 0.80, (1 − p_min) = 0.20, (n−1) = 2 Término 1: −0.80 × log₂(0.80) = −0.80 × (−0.3219) = +0.2575 Término 2: −0.20 × log₂(0.20/2) = −0.20 × log₂(0.10) = −0.20 × (−3.3219) = +0.6644 H_stop = 0.2575 + 0.6644 = 0.922 bits

Entropía inicial y barra de progreso

\[ H_0 = \log_2 3 \approx 1{,}585 \text{ bits} \qquad\longrightarrow\qquad H_\text{stop} \approx 0{,}922 \text{ bits} \]

El recorrido a cubrir es \(H_0 - H_\text{stop} \approx 0{,}663\) bits. La barra de progreso refleja qué fracción de ese recorrido se ha completado:

\[ \text{progreso} = \frac{H_0 - H(\pi)}{H_0 - H_\text{stop}} = \frac{1{,}585 - H(\pi)}{0{,}663} \]

Ejemplo tras el primer fallo (pregunta media):

Progreso tras 1 pregunta — H(π) = 1,375 bits
32 %  ·  (1,585 − 1,375) / 0,663 = 0,210 / 0,663 ≈ 0,32

8. Número máximo de preguntas: búsqueda minimax

¿Cuántas preguntas son necesarias en el peor caso posible antes de que la entropía caiga bajo \(H_\text{stop}\)? Ese valor es \(MAX\_Q\).

Para calcularlo, el sistema construye un árbol de decisión recursivo:

  1. En cada nodo del árbol, el sistema selecciona la pregunta con mayor IG usando el prior actual.
  2. Desde ese nodo se bifurcan dos ramas: una para acierto y otra para fallo.
  3. En cada rama se calcula el nuevo prior y se repite el proceso.
  4. Si el nuevo prior ya cumple \(H < H_\text{stop}\), esa rama termina.
  5. El número máximo de preguntas es la profundidad máxima del árbol antes de que todas las ramas hayan terminado.
\[ MAX\_Q = \min\{k : \text{el árbol completo de profundidad } k \text{ cubre todos los casos}\} \]

Como el árbol real sería demasiado grande (depende de qué preguntas concretas estén disponibles), el cálculo usa preguntas representativas abstractas: una fácil, una media y una difícil, con \(m_q = 4\). La búsqueda se hace con memoización para evitar recalcular distribuciones ya visitadas.

Garantía de terminación \(MAX\_Q\) garantiza que el test siempre termina en como máximo ese número de preguntas, sea cual sea la secuencia de respuestas del alumno. No es un promedio: es el peor caso. En la práctica, la mayoría de sesiones terminan bastante antes.

9. Aleatorización justa: Fisher-Yates y selección ponderada

Por qué no basta con sort(Math.random())

El truco popular de barajar un array con array.sort(() => Math.random() - 0.5) produce permutaciones sesgadas. El motor de ordenación de JavaScript (TimSort) no llama al comparador el mismo número de veces para todos los pares, lo que hace que algunos elementos acaben al principio con mayor frecuencia que otros.

El sistema usa el algoritmo de Fisher-Yates, que garantiza una distribución uniforme sobre todas las \(n!\) permutaciones posibles:

-- Fisher-Yates (versión Knuth-Durstenfeld) for i = n−1 downto 1: j = entero aleatorio uniforme en [0, i] intercambiar arr[i] y arr[j]

En cada paso, el elemento que irá a la posición \(i\) se elige con probabilidad \(1/(i+1)\) entre los que aún no se han colocado. La probabilidad de cualquier permutación es exactamente \(1/n!\).

Selección aleatoria ponderada entre empates

Muchas preguntas tienen exactamente la misma IG (especialmente cuando comparten dificultad y número de opciones). Una selección determinista entre empates produciría tests repetitivos.

El sistema resuelve esto con selección ponderada inversamente por categoría:

  1. Se calcula la IG de todas las preguntas disponibles.
  2. Se forman las candidatas: todas las que tienen \(IG \geq IG_\max - \varepsilon\) (con \(\varepsilon = 10^{-9}\)).
  3. A cada candidata se le asigna un peso \(w_q = 1 \big/ (1 + \text{veces que ya ha aparecido su categoría})\).
  4. Se elige una candidata con probabilidad proporcional a su peso.

Si la categoría «Historia» ya ha aparecido 2 veces y «Ciencia» 0 veces, los pesos respectivos son \(1/3\) y \(1/1 = 1\): Ciencia tiene tres veces más probabilidad de ser elegida. Esto garantiza diversidad de contenidos sin renunciar a la utilidad informativa.

11. Convergencia: por qué el sistema aprende

La actualización bayesiana garantiza que, con respuestas consistentes, la distribución converge hacia la hipótesis verdadera. El mecanismo es algebraicamente sencillo.

Por qué la hipótesis verdadera acumula ventaja

Supongamos que el nivel real del alumno es Básico. Tras \(n\) respuestas, la probabilidad de cada hipótesis es proporcional al producto de sus verosimilitudes:

\[ \pi^{(n)}_i \propto \pi^{(0)}_i \cdot \prod_{k=1}^{n} P(R_k \mid H_i) \]

Para que Básico acumule más que Medio, basta con que el producto de sus verosimilitudes sea mayor:

\[ \prod_{k=1}^{n} P(R_k \mid H_0) > \prod_{k=1}^{n} P(R_k \mid H_1) \]

Esto ocurre cuando las respuestas son consistentes con el nivel básico: fallos en preguntas medias y difíciles, aciertos en fáciles. Cada respuesta que sigue ese patrón multiplica la probabilidad de Básico por un factor \(> 1\) relativo a Medio.

Papel de la entropía

La entropía cae porque los productos de verosimilitudes son distintos para cada hipótesis. Una vez que una hipótesis tiene mucha más probabilidad acumulada que las demás, los nuevos datos la refuerzan aún más (retroalimentación positiva), y la entropía cae rápidamente.

¿Qué pasa con respuestas inconsistentes?

Si el alumno acierta preguntas difíciles pero falla preguntas fáciles, las verosimilitudes de cada hipótesis se compensan parcialmente. La distribución no converge hacia ningún nivel y la entropía permanece alta. El sistema lo detecta y, si se alcanza \(MAX\_Q\), presenta el resultado como estimación provisional. Esta honestidad sobre la incertidumbre es una característica del diseño, no un defecto.

Límite del modelo Si el alumno responde al azar, las verosimilitudes de acierto y fallo para cada hipótesis son aproximadamente iguales (porque el suelo \(c_q = 0{,}25\) garantiza que incluso el nivel más bajo acierta con cierta frecuencia). En ese caso la distribución no converge, la entropía no cae, y el test termina por límite de preguntas con diagnóstico provisional. El sistema no puede distinguir entre un alumno que no sabe y uno que responde aleatoriamente.

Recuperación automática

Si el alumno falla las primeras preguntas pero luego acierta preguntas difíciles, el posterior se desplaza: la probabilidad de Básico sube inicialmente, pero los aciertos en preguntas difíciles tienen verosimilitudes muy desfavorables para Básico (\(P(\text{acierto}\mid H_0, b=1) = 28{,}6\%\)) y muy favorables para Avanzado (\(86{,}3\%\) para Avanzado en una difícil). Tras suficientes aciertos difíciles, Avanzado recupera probabilidad de forma automática, sin ninguna lógica de recuperación adicional. La recuperación es gradual y proporcional a la evidencia acumulada.
